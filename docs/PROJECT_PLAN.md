# 项目实施计划

## 项目定位

作品名称：**全球化增长内容 Agent（CapCut 公开资料案例）**。目标用户是需要为视频编辑产品制作英语和西班牙语增长内容的运营编辑。系统交付 SEO 短页面草稿、两条社媒文案、逐条事实依据和待人工审核包。CapCut 是公开资料案例，项目不是官方产品，也不调用其内部接口。

## 可演示的最小闭环

1. 编辑输入语言、受众、搜索意图、种子关键词和产品功能。
2. `search_knowledge` 通过 MCP 检索带 URL、检查日期和引文的功能事实卡；找不到证据就停止。
3. 生成器使用检索结果生成标题、描述、正文和社媒文案。离线模板用于开发验证；接入模型后才能评估生成质量。
4. `check_draft` 通过 MCP 检查未知证据 ID、禁用表述与未经资料支持的数字，并记录局限。
5. 导出 JSON 与 Markdown，编辑逐条核对来源，记录批准或退回决定。发布由真实业务人员另行完成。

## 接下来四个里程碑

| 阶段 | 工作 | 验收证据 |
|---|---|---|
| 1. 可运行原型 | 官方事实卡、双语离线流程、MCP、审核包、基础测试 | 六条样例可运行；资料不足案例正确停止；没有任何自动发布 |
| 2. 模型接入 | 配置本地或兼容 API 模型；固定 Prompt 版本和 JSON 合约；失败限次修复 | 至少两种语言的真实模型输出、调用轨迹与失败样例 |
| 3. 离线评测 | 标注开发集与冻结测试集；运行 A/B/C 消融；双语人工盲评 | 可复现评测脚本、原始结果、人工评分表和误差分析 |
| 4. 作品展示 | 简短 Web/CLI 演示、架构图、README、录屏与模型卡 | 面试时五分钟内演示成功样例、拒答样例及评测报告 |

## 最重要的工程边界

- MCP 是工具调用协议：展示进程内 `Client` 真正调用服务器工具、参数校验、错误反馈和轨迹，而不是给普通 Python 函数改名。
- 规则检查不是语义事实核验。即使程序通过，也必须让编辑检查主张与来源片段是否真正对应。
- 保存资料核对日期和适用性备注；定价、地区、套餐、语言数量、准确率等易变信息不自动承诺。
- 有自己的站点并发布后，才能讨论 Search Console 展示、点击和 CTR。草稿质量指标与 SEO 效果分开。

## 面试演示路径

选择一条 `auto-captions` 英语 brief：展示输入、MCP 检索事实、生成内容、证据链接、护栏结果和人审包。再选择“AI 配音全球免费且 100% 准确”的难例，展示证据不足时系统停止。最后展示同一模型下 A/B/C 的评测记录；在模型与评测完成前，该部分只能作为计划介绍。
