# 评测记录与后续设计

离线模板样例只用于检验工作流。2026-09-30 已在 AutoDL RTX 3090 上用 `qwen3:4b-instruct` 跑完 24 条真实模型评测。v2 原始版本流程成功 18/24；v4 对有效位置的引用句增加可审计对齐后，回归成功 21/24、正确弃答 6/6。完整报告和解释见 `docs/STATE.md`。这些只量度工作流与证据 ID，尚未进行人工语义事实或营销质量盲审。v4 使用同一批输入再次运行，应称为回归，不应称为新的未见测试集。

以下是后续若要比较单次 Prompt、一次性 RAG 与完整 Agent 的设计，目前未执行该三组对照。

## 数据划分与标注

- 先做约 8 条开发 brief 用于改 Prompt 和规则；再冻结约 12–16 条未见 brief，每条分别做 `en-US` 与 `es-ES`。测试集至少四分之一为资料缺失、地区适用性或夸大措辞难例。
- 每条 brief 标注 3–5 个必须覆盖的原子事实、不得写出的主张、可支持它们的来源片段、搜索意图和预期的弃答行为。记录标注人、标注日期与来源版本。
- 测试集封存后不再用来调 Prompt。需要修改时另开版本，保留旧结果。

## 三组对照

| 组 | 条件 |
|---|---|
| A 单次 Prompt | 相同模型、相同 brief，不给检索结果或工具。 |
| B 一次性 RAG | 相同模型、相同 brief，给同一检索器返回的事实卡，一次生成。 |
| C 完整 Agent | 相同模型与检索器，增加 MCP 调用、确定性护栏、有限修订和审核包。 |

固定温度、最大输出长度和输出格式。每个 brief 记录输入/输出 token、调用次数、耗时、失败原因与模型版本。C 的额外工具成本也计入总成本。

## 指标定义

1. **有证据支持的主张比例** = 经人工核对、真正被来源片段支持的原子产品主张数 / 输出的全部原子产品主张数。并列报告主张总数，防止靠少写获得高分。
2. **必需事实覆盖率** = 正确覆盖的金标准事实数 / 金标准必需事实总数。
3. **引用支持率** = 引用确实支持对应主张的次数 / 有引用的产品主张数。
4. **正确弃答率** = 遇到不可证实要求时明确拒绝相关承诺的次数 / 不可证实要求总次数。
5. **人工可用性**：两名具相应语言能力的评审随机、隐藏组别打分，分别评价事实、意图匹配、本地化自然度和可编辑性；记录十分钟内是否可修改到可发布，以及实际编辑分钟数。
6. **工程指标**：完整任务成功率、P50/P95 总耗时、单任务 token 与实际费用（若计费信息可得）。

按同一 brief 的 A/B/C 成对报告结果和失败案例。小样本如实给出分子、分母与不确定性，不把离线指标称为排名、流量或转化提升。
